# Portfolio Maintenance — 2026-09-15

## Review focus
- Keep project descriptions aligned with the technologies actually used in each repository.
- Prefer evidence-backed README claims: runnable setup steps, tests, CI status, and concrete features.
- Keep screenshots and demo links current when a project UI changes.
- Remove stale instructions when tooling, framework versions, or entry points change.

## Quality bar
A portfolio repository should make it easy for a reviewer to answer four questions: what the project does, how to run it, how it is tested, and what engineering decisions it demonstrates.

## Follow-up
- Recheck setup commands after dependency upgrades.
- Keep API examples synchronized with implementation.
- Record meaningful feature work in project documentation rather than creating activity-only commits.
