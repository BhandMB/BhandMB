# Portfolio Project Evidence and Demo Checklist

Date: 2026-11-20

## Objective

Make each public project easy for a reviewer to understand and verify.

## Repository presentation

- State the problem, intended users, and core features in the README.
- List the actual technology versions and prerequisites.
- Provide reproducible setup and configuration steps without committing secrets.
- Include architecture notes and API examples where relevant.
- Explain known limitations honestly.

## Evidence quality

Prefer screenshots, short demo recordings, API examples, test reports, and links to meaningful source files. Ensure each item reflects the current default branch. Do not describe planned features as completed.

## Interview preparation

For each project, prepare a concise explanation of one design decision, one difficult bug, one security consideration, and one possible next improvement. Be ready to explain code personally rather than relying only on README claims.

## Review checklist

- [ ] Setup works from a clean clone.
- [ ] Secrets and local data are excluded.
- [ ] Screenshots match the current UI.
- [ ] Tests are described accurately.
- [ ] Limitations and future work are explicit.

## Scope

This checklist does not certify that any repository currently passes these checks.
