# Portfolio Architecture Notes

## Purpose
This note records how the portfolio projects demonstrate backend, client, and delivery skills.

## Project signals
- `book-library-api`: REST design, validation, persistence, and API documentation.
- `employee-management-system`: CRUD workflows, role-aware behavior, and maintainability.
- `book-library-app`: client integration, empty states, and error handling.
- `MiniATM`: domain rules, state transitions, and deterministic test cases.
- `LogoGuessApp`: Android UI flow, local assets, and release checks.

## Review questions
1. Can a new contributor run the project from the README alone?
2. Is the happy path covered by at least one automated or repeatable test?
3. Are failure modes visible and actionable?
4. Does the repository show a clear next improvement?
