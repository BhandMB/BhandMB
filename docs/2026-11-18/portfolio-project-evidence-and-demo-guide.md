# Portfolio Project Evidence and Demo Guide

## Purpose
Help reviewers verify project claims quickly through reproducible evidence rather than broad skill lists.

## Per-project evidence
For each repository, document:
- Problem the project solves and intended users.
- Architecture and major technology choices.
- Setup steps that work from a clean checkout.
- Key API routes or user workflows.
- Tests that can be run and their actual latest result.
- Known limitations and next improvements.
- Screenshots or a short demo where appropriate.

## Claim quality
Separate implemented features from planned work. Mention tools only when they are present in the repository and can be explained in an interview. Never describe a test as passing unless it was run and its result recorded.

## Demo sequence
Start from a clean environment, show the main user journey, demonstrate one meaningful validation or authorization case, and explain one design trade-off. Keep demo credentials clearly marked as disposable and never use production secrets.

## Maintenance
Review links, setup commands, dependency versions, and screenshots after material changes. Keep the profile README concise and link to the strongest evidence first.
