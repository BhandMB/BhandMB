# Contribution Quality Gates

Use these gates for portfolio changes:

1. The change solves a real maintenance, usability, correctness, or documentation need.
2. The commit message explains the outcome, not just the file name.
3. Documentation matches the current repository behavior.
4. Tests or manual verification steps are included for behavior changes.
5. No secrets, credentials, generated binaries, or machine-specific paths are added.
6. The default branch remains buildable after the change.

Prefer small, reviewable commits that can be explained in an interview.
